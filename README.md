# Журналка

Санитарные журналы общепита в телефоне.

Кабинет: https://zhurnalka.vercel.app/app/
Mini App (этот PR, после настройки бота): https://zhurnalka.vercel.app/tg/


## Структура

```
public/          — сайт и кабинет /app/, Mini App /tg/
api/*.js         — функции Vercel (обёртки)
srv/             — сервер: бот, вход, агенты, cron
sql/             — схема для локальных тестов и миграция входа
test/            — автотесты
scripts/tg-setup.js — разовая настройка бота, запускает человек
```

Деплой на Vercel идёт из монорепозитория **dancekilla1999-gif/trio** (папка с тем же именем).
Секреты — только в переменных окружения. В репозиторий их не кладём.

## Telegram Mini App

Вход в кабинет из Telegram. Человек один раз привязывает аккаунт (кнопка «Привязать Telegram» на сайте или почта и пароль в Mini App). Дальше каждое открытие входит само по `initData`. Сессия кончается только при выходе, смене пароля или отключении.

Регистрация на сайте только по одноразовой ссылке-приглашению. Публичной формы нет: `/app/#/register` без `invite` показывает отказ. Ссылку создаёт вошедший владелец в разделе «Аккаунт».

Печать в Telegram открывает ту же страницу на сайте. Оплата в Mini App не показывается: только нейтральный статус тарифа.

### База

Боевую базу Supabase (`qozyihhlocvgpkchyqsp`) этот PR не меняет. Миграция лежит файлом:

`sql/20261126_tg_auth.sql`

Её применяет человек после проверки. Отдельного тестового проекта Supabase пока нет, поэтому тесты поднимают **Postgres 17**:

- локально: `docker compose up -d` и `TEST_DATABASE_URL=postgres://postgres:postgres@127.0.0.1:5432/zhurnalka npm test`
- в GitHub Actions — сервис `postgres:17`

Сначала загружается минимальная схема `sql/test_schema.sql` (роли `anon`, `authenticated`, `service_role`, расширение `pgcrypto`), затем миграция. Когда появится тестовый проект Supabase, тот же прогон идёт по `TEST_DATABASE_URL`.

### Бот

Скрипт `scripts/tg-setup.js` сам ничего не делает, пока `TG_SETUP` не равен `1`. Деплой и cron бота не трогают.

Человек, когда токен уже лежит в секретах:

1. В BotFather создать бота (или оставить существующего Журналки) и указать ссылку на политику `/legal/privacy.html`.
2. Положить токен в `TG_BOT_TOKEN`, придумать `TELEGRAM_WEBHOOK_SECRET` и `TG_SESSION_SECRET`.
3. Запустить: `TG_SETUP=1 PUBLIC_URL=https://zhurnalka.vercel.app node scripts/tg-setup.js`
4. Проверить `getWebhookInfo` и команду `/start`.

`/start` с 18-hex кодом по-прежнему привязывает чат отчётов. Код `l_…` чат не привязывает: это вход в кабинет.

Ротация токена: `/revoke` в BotFather, новый токен в секрет, новый `TELEGRAM_WEBHOOK_SECRET`, перезапуск, снова `tg-setup.js`, проверка `/start`.

### Регион

В `vercel.json` указано `"regions": ["fra1"]`. Пока заголовок `x-vercel-id` превью не покажет `fra1::`, в тексте пишем: функции Vercel — США (по умолчанию `iad1`), база Supabase — ЕС (Франкфурт). Этап 2 — перенос origin и базы в РФ, не позже 10.12.2026.

Политика (`public/legal/privacy.html`) описывает, что мы берём из Telegram. Реквизиты самозанятого (ИНН, адрес, почта) дополняются до уведомления РКН. Уведомление мы не отправляем.
